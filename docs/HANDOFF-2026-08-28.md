## 2. The one real blocker, and its fix

`eth0` had carrier but no IPv4, stuck at "getting IP configuration".
The NetworkManager profile was `ipv4.method: auto` (DHCP); the ZGW
serves no DHCP because ENET expects the host to self-assign IPv4
link-local. Discovery therefore found nothing.

```bash
sudo nmcli connection modify netplan-eth0 \
    ipv4.method link-local ipv4.may-fail yes ipv6.method ignore
```

Persistent, survives reboot, scoped to `eth0` only. This is **the single
most important thing to know** about running this Pi, and it was
previously documented incorrectly — `RUN_IN_CAR.md` claimed a Pi
self-assigns link-local natively. Corrected this session.

## 4. Drive 6 — results

**It fragmented into 7 runs.** The ENET cable lost carrier for 2m46s

### The finding worth keeping

> **OBD MAP saturates at 255 kPa** while the DDE reads true manifold
> pressure to 272 kPa.

The recurring ⚠️ on the boost cross-check line in *every previous
report* was generic-sensor saturation, never a decode error. Above
250 kPa `n47d_boost_act` is the accurate channel and any boost analytics
should prefer it. This is a direct vindication of the proprietary
channel set.

## 5. Network and exposure — the boundary

Uplink is an iPhone hotspot plus WireGuard to the VPS. Measured over
cellular: 97 ms to the VPS, 6.1 Mbit/s up, ingest `/health` in 0.25 s.
The wire format costs **2.4 bytes/sample**, so a whole drive is a few MB.

**Only the dashboard UI (port 8080) is public**, by request:

- Pi: `f10-tunnel.service` runs `ssh -NT -R 0.0.0.0:8080:127.0.0.1:8080`
  with `Restart=always` and keepalives, so it survives hotspot blips.
- VPS: `GatewayPorts clientspecified` added to `sshd_config` (backup
  kept), `ufw allow 8080/tcp`.

**Ingest (8090) and the sync control endpoint (8091) are NOT public and
must stay that way.** Sync points at the ingest server *over WireGuard*
so the bearer token never crosses the open internet.

> During this session 8091 was briefly added to the tunnel to make the
> dashboard's sync indicator work remotely. **That was a mistake and was
> reverted the same session.** 8091 exposes unauthenticated
> `/sync/pause` and `/sync/resume`. It was never actually reachable —
> ufw's `INPUT DROP` had no 8091 rule — but do not re-add it. The
> correct fix is §7.1.

## 7. Open items for the laptop, in priority order

### 7.1 Dashboard sync indicator reads "off" remotely
The page hardcodes `http://<location.hostname>:8091/sync/status`
(live.py:1964). Through the tunnel that resolves to the VPS, where 8091
is deliberately closed, so the fetch times out and the `catch` paints the
dot red (live.py:1978). **Sync itself is unaffected** — it was verified
`synced`, 0 pending, throughout.
**Fix:** a same-origin, read-only `/api/sync` endpoint in `live.py`
proxying `127.0.0.1:8091`, with the page pointed at it. One tunneled
port, no second firewall hole, no pause/resume exposed.

### 7.2 The public dashboard serves the VIN
`/api/snapshot` includes a `vin` field and the tunnel has no auth, so the
VIN is reachable by anyone who finds port 8080. This is contrary to the
project's "no VIN leaves the box" rule. Fix is a one-line omission from
the snapshot payload — the dashboard does not need it to render — and/or
an IP allowlist on 8080. **Decide on this before the next public drive.**

### 7.3 ClickHouse is OOMing on background merges
1.9 GB RAM, CH capped at 840 MiB. A merge died with
`MEMORY_LIMIT_EXCEEDED`; an ad-hoc query on `system.text_log` was killed
by the same limit. Cause: CH's own logs dwarf the telemetry —
`text_log` 30.9 MiB, `metric_log` 30.7 MiB,
`asynchronous_metric_log` 20.8 MiB (34 M rows) against
`telemetry.samples` at 6.18 MiB. Fix: TTL the system log tables to ~7
days, disable `asynchronous_metric_log` and `trace_log`.

### 7.4 Sessions never closed
32 of 58 `sessions` rows in ClickHouse have `ended IS NULL`. Only a clean
SIGINT writes `ended_at`; a transport reconnect starts a new run and
leaves the old one open — the same mechanism that produced 7 runs in
drive 6. Cosmetic now, will skew session-duration analytics later.

### 7.5 Auto-start the logger and sync agent
Two systemd units, mirroring `f10-tunnel.service`. Would make the Pi
genuinely turn-key: power on, drive, data lands.

### 7.6 Still the biggest unbuilt piece
The analytics layer — condition-normalised baselines and drift detection,
`ROADMAP.md` stages 3–5. The lake is deployed, accumulating, and now fed
automatically from the car. Drive 6 produced the first comparable
longitudinal pair (§4). This remains the highest-value next domain and is
unblocked.
